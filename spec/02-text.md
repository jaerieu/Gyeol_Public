# 2. 글자와 정규화

## 2.1 문자의 역할

| 문자 | 맡는 것 | 유니코드 범위 |
| --- | --- | --- |
| 한자 | 내용의 어근 | 문자 체계 속성이 Han인 글자 |
| 한글 | 표지, 조사·어미, 열쇠말, 소리 표기 | 문자 체계 속성이 Hangul인 글자 |
| 로마자 | 덧글, 고유명사, 기술 용어 | 라틴 문자, 숫자, `-` `_` `'` `.` |

한자는 뜻의 닻이다. 다만 필담이 성립한 것은 한자만이 아니라 한문 문법까지 공유했기 때문이므로(12장 정정 5), 결은 핵(점)을 한국어 문법 없이 어근과 정의된 표지만으로 읽히게 만든다. 한국어 조사·어미는 펼침에서만 쓴다.

## 2.2 구조 기호

정규형은 아래 코드 포인트만 쓴다. 구문 분석기는 오른쪽 열의 비슷한 기호도 받아서 정규형으로 바꿔야 한다. 다른 회사 모델이 비슷한 기호를 섞어 쓰기 때문이다.

| 뜻 | 정규형 | 받아들이는 비슷한 기호 |
| --- | --- | --- |
| 표지 블록 | `〈` U+3008, `〉` U+3009 | `⟨⟩` `《》` `＜＞` `<>` |
| 먹 블록 | `〔` U+3014, `〕` U+3015 | `［］` `[]` `⦗⦘` |
| 채 블록 | `「` U+300C, `」` U+300D | `『』` `｢｣` |
| 구분점 | `·` U+00B7 | `・` `･` `•` `ㆍ` `‧` `⋅` `∙`. 표지 블록 안에서는 `,` `/`도, 먹·채 블록 안에서는 `,` `;`도 |
| 아래(근거·단서) | `↓` U+2193 | `⇣` |
| 맞섬 | `↔` U+2194 | `<->` `⇄` |
| 버린 대안 | `∥` U+2225 | `\|\|` `‖` |
| 향함 | `→` U+2192 | `->` `⇒` |
| 되물을 곳 | `↖` U+2196 | `^` |
| 답하는 대상 | `↩` U+21A9 | `re:` |

`【】`는 시험지의 단락 제목에 쓰므로 먹 블록의 비슷한 기호로 받지 않는다.

## 2.3 두 가지 정규화

### 문서 정규화

사전, 짝 약속, 시험지처럼 결 문법으로 구문 분석하지 않는 글에 쓴다. v0의 규칙과 같으므로 기본 사전 v0의 먹 이름 `#8811fa`는 바뀌지 않는다.

1. 줄바꿈을 LF로 바꾼다(CRLF, CR → LF).
2. 유니코드 NFC로 정규화한다.
3. 각 줄 끝의 공백과 탭을 지운다.
4. 끝의 빈 줄을 지운다.
5. 마지막에 LF 하나를 붙인다.

### 메시지 정규형

결 메시지는 구문 분석한 뒤 정해진 방식으로 다시 쓴 것을 정규형으로 한다(3.9절). 그래서 비슷한 기호, 띄어쓰기, 수의 표기, 먹 항목의 순서가 달라도 같은 메시지면 정규형이 같고 먹 이름도 같다.

## 2.4 수

먹과 채의 값은 0~1의 확률·비율이다.

- 정규형은 소수 둘째 자리까지 쓰고 앞의 0을 뺀다: `.72`, `.05`, `.00`. 1은 `1.00`으로 쓴다.
- 받아들이는 입력: `0.72`, `.72`, `72%`, `.7`(→ `.70`), `1`(→ `1.00`).
- 셋째 자리 이하는 둘째 자리에서 반올림한다. 0.5는 올린다. 구현은 부동소수점이 아니라 십진 문자열로 계산한다. 이때 검사기는 경고를 낸다.
- 0보다 작거나 1보다 큰 값은 오류다.

## 2.5 어절

내용은 공백으로 나눈 어절의 줄이다. 어절은 넷 중 하나다.

| 어절 | 모양 | 예 | 점으로 접을 때 |
| --- | --- | --- | --- |
| 어근 어절 | 한자 하나 이상 + 한글 꼬리(없어도 됨) | `新法을`, `得했다`, `雨` | 꼬리를 떼고 어근만 남긴다 |
| 로마자 어절 | 로마자·숫자 + 한글 꼬리(없어도 됨) | `API를`, `GPT` | 꼬리를 떼고 남긴다 |
| 수 어절 | 숫자 | `3`, `2026` | 남긴다 |
| 한글 어절 | 한글만 | `그리고`, `아주` | 지운다 |

- 한 어절 안에서 한글 꼬리 뒤에 다시 한자가 오면 오류다(`新法을得`). 띄어 써야 한다.
- v0.5부터 새 꼴 줄의 어절은 어느 언어의 글자로 쓰든 읽고(3.14절 '내용'), v0.5.2부터 0.5.1 꼴 절의 내용은 문장부호·수 연산 기호·일상 기호도 쓴 그대로 받는다(문법 기호와 그림 문자만 막는다, 3.16절). 이 표는 옛 꼴의 어절이다.
- 한자 어근 사이의 띄어쓰기는 뜻을 바꾸지 않는다. 그래서 핵을 비교할 때는 어근을 글자 단위로 이어 붙여 비교한다(7.4절). `整列 新法`과 `整列新法`은 핵이 같다.

## 2.6 기준 글꼴과 이체자

같은 글자가 간체, 번체(정자), 일본 신자체로 다르게 적힐 수 있다(`变`·`變`·`変`). 결의 기준 글꼴은 **간체**다(2026-10-13 Jae 결정).

### 근거

세 갈래가 '주류 언어 모델은 간체를 더 잘, 더 싸게 다룬다'는 쪽을 함께 가리킨다. 서로 다른 방법(평가 점수, 모델 개발 보고, 토크나이저 압축률)에서 나온 결과라 함께 놓으면 꽤 강하다.

- 번체 평가 묶음 TMMLU+에서 간체 중심 모델이 같은 크기의 번체 중심 모델보다 19% 이상 앞섰고, 간체 질문이 다국어 모델과 간체 모델의 성능을 크게 올렸다(Tam 외 2024).
- 번체 모델을 만든 쪽은 GPT-4와 Claude 2 같은 모델이 주로 영어와 간체로 학습되었다고 보고했다(Lin·Chen 2023).
- 번체 말뭉치에 맞춰 낱말 목록을 늘리자 Mistral 토크나이저보다 압축률이 약 두 배가 되었다(Breeze-7B 보고서, 2024). 기존 토크나이저가 번체를 비싸게 쪼갠다는 뜻이다.

세 결과 모두 중국어 문장으로 된 과제에서 나왔다. 결처럼 한국어 문법 안에 어근만 섞어 쓰는 조건에서도 같은지는 아직 재지 않았다. 그래서 첫 교차 검증에서 같은 시험지를 간체판과 번체판으로 나눠 비교한다(11장, `packets/v0.2/A-정자.txt`).

### 간체로 합쳐진 글자

간체화는 서로 다른 번체 여러 자를 한 글자로 합쳤다. Unihan 자료에서 둘 이상의 번체로 갈리는 간체는 485자다. `复`(復·複·覆), `后`(后·後), `干`(乾·干·幹), `发`(發·髮), `系`(係·系·繫) 같은 자주 쓰는 글자가 들어 있다. 맥락이 적은 점에서는 이 합침이 뜻을 흐릴 수 있다.

- 합쳐진 간체를 핵의 어근으로 쓸 때는, 뜻이 갈리면 조율 용어로 뜻을 정해 두는 것이 좋다(7장).
- 꾸러미를 만드는 도구는 간체를 번체로 되돌릴 때 갈리는 글자를 만나면 멈춘다(`packets/build.ts`).

### 규칙

- 쓰는 쪽은 간체를 쓰는 것이 좋다. 번체나 일본 신자체를 써도 오류가 아니다. 검사기는 간체가 따로 있는 글자에 경고(W03)를 낸다.
- 정규형은 글자를 바꾸지 않는다. NFC 외의 글자 변환은 먹 이름을 흔들기 때문이다.
- 핵을 비교할 때는 이체자 대응표(`dict/variants-v0.2.json`)로 같은 글자를 가린다. 대응표는 유니코드 Unihan 자료에서 만든다(`tools/build-variants.ts`).
    - 글자 c의 번체 집합 T(c)는 간체→번체 대응, Z 이체, 뜻이 완전히 같다고 표시된 의미 이체(`:T`)를 모은 것이다.
    - 두 글자 a, b는 T(a)∪{a}와 T(b)∪{b}가 겹치면 같다. 이 관계는 이행적으로 넓히지 않는다. 그래서 `发`은 `發`과도 `髮`과도 같지만, `發`과 `髮`은 서로 다르다.
    - Unihan은 일본 신자체를 일부만 덮는다. `変`은 `變`과 같다고 나오지만 `読`·`讀`은 대응이 없다. 빠진 대응은 V14 결과를 보며 손으로 더한다.
- 번체를 간체로 옮기는 도구: `node tools/cli.ts simplify <파일>`.
