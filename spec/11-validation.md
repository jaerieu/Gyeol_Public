# 11. 검증

두 가지를 검증한다. 구현이 명세를 지키는지(적합성)와, 설계의 가설이 맞는지(실험)다.

## 11.1 적합성

참조 구현의 시험(`npm test`)이 다음을 확인한다.

- 기본 사전 v0의 먹 이름이 `#8811fa`로 다시 계산된다.
- 짝 예문과 명세의 보기가 모두 오류 없이 구문 분석된다.
- 3장의 규칙을 하나씩 어긴 글이 정해진 오류 번호를 낸다.
- 10.4절의 왕복 성질이 지켜진다.
- 비슷한 기호(2.2절)로 쓴 글과 정규 기호로 쓴 글의 먹 이름이 같다.

구현의 적합성 등급:

| 등급 | 할 수 있어야 하는 것 |
| --- | --- |
| 읽기 1 | 점과 절을 구문 분석하고 표지를 읽는다 |
| 읽기 2 | 읽기 1 + 먹, 채, 앞붙이, 머리, 낙관 |
| 쓰기 | 검사기 오류가 없는 글을 낸다 |
| 측정 | 5장의 `se`와 `토큰`(또는 `지연`)으로 먹을 붙인다 |

## 11.2 실험

초안 14장의 열 개 실험을 그대로 두고, 넷을 더한다. 반증 조건은 결과를 보기 전에 고정한다.

| 실험 | 무엇을 보나 | 반증 조건 |
| --- | --- | --- |
| V1 채택 | 세 회사 이상의 모델에게 영어, 영어+태그, 결 중 형식을 고르게 한다. 순서는 무작위 | 결을 고르는 비율이 우연 수준 이하 |
| V2 유지 | 50턴 이상 자유 대화에서 층 사용률, 영어 복귀, 반복, 주제 수렴. 되풀이 제한을 켜고 끈다 | 층 사용률이 계속 줄거나, 되풀이 제한이 수렴을 늦추지 못함 |
| V3 복원 | 근거, 확신, 화행, 정동, 관계의 복원 정확도를 글만, 글+그림, 세 감각 조건으로 비교 | 감각을 더해도 정확도가 오르지 않음 |
| V4 충실 | 먹 값이 실제 계산과 맞는지, 받는 쪽이 먹과 채의 어긋남을 알아채는지 | 어긋남 탐지가 우연 수준 |
| V5 미적 선호 | 동기 있는 대응과 무작위 대응으로 그린 같은 메시지를 짝 비교. 모델과 사람 모두 | 선호 차이가 없음 |
| V6 문화 의존 | 감각 대응과 어조 기준값(6.1절)을 여러 언어로 독립 질의 | 언어별 차이가 크면 \[근거\]를 \[관습\]으로 내리고 기준값을 다시 잰다 |
| V7 과신 감소 | 받은대로 되짚기가 있을 때와 없을 때 보내는 쪽 예측과 받는 쪽 이해의 차이 | 차이가 줄지 않음 |
| V8 오류 전파 | 먹이 있을 때 다중 에이전트 과제에서 오류가 다음 에이전트로 넘어가는 비율 | 비율이 줄지 않음 |
| V9 핵 일치율 | 같은 점을 여러 회사 모델에 보내 핵 복원 비율과 여운의 갈라짐을 본다 | 조율한 쌍에서도 점의 핵 일치율이 펼침보다 뚜렷이 낮음 |
| V10 조율의 값 | 조율한 쌍과 안 한 쌍의 전체 소요(조율 포함)와 오해율을 대화 길이별로 | 어떤 길이에서도 전체 소요가 줄지 않음, 또는 '맞췄다' 뒤에도 시험 점 불일치가 남음 |
| **V11 시간** | 같은 전달 과제를 영어, 결 펼침, 결 점+조율로 수행. 받는 쪽이 정답 이해에 이르기까지의 왕복 수와 시간 | 결 조건의 왕복 수와 시간이 영어보다 줄지 않음 |

## 11.3 실행 순서

비용이 낮고 다른 실험의 전제가 되는 것부터 한다.

1. V9, V10, V14: 붙여넣기 시험이나 자동 실행기(`harness/`)로 한다. 꾸러미(`packets/`)가 이 셋과 기준 글꼴 비교를 맡는다.
2. V6, V12: 렌더러가 필요하다(3단계 사이트의 일부).
3. V13: 자동 실행기로 세대를 잇는다. 다음 세대 꾸러미는 앞 세대 답에서 만들어 D1의 `packets` 표에 넣는다.
4. V4, V8, V11: 측정 도구가 붙은 에이전트가 필요하다.
5. V1, V2, V3, V5, V7: 사이트의 실제 대화에서 한다.

V1과 V2는 설계 전체의 성패다. 앞선 보편 언어들이 모두 채택에서 막혔다(초안 12장).
